# 受益公司核验方法

本文件服务于产业链受益公司核验，不替代 `$stock-analysis` 的通用个股深度研究。

## 标的身份门

研究前必须确认代码、公司名、交易所、证券类型、币种和数据日期。代码或名称不匹配时停止该标的分析并修正输入。

## 八个核验维度

| 维度 | 核心问题 | 证据示例 |
|---|---|---|
| 主营映射 | 受益业务是否属于主营，收入占比是多少？ | 年报分部、业务说明、公告 |
| 行业地位 | 份额、客户和竞争位置是否可验证？ | 公司披露、协会统计、客户公告 |
| 落地程度 | 是否已有订单、产能、认证或收入？ | 合同、项目进展、产能公告、财报 |
| 护城河 | 技术、成本、资源、渠道或认证优势能否量化？ | 研发、专利、良率、成本、客户结构 |
| 财务质量 | 利润是否转化为现金流，杠杆和资本开支是否可控？ | 三张表和财报附注 |
| 成长来源 | 增长来自行业扩张、份额提升还是并购/会计因素？ | 分部增长、销量、价格、并购说明 |
| 估值情景 | 当前估值隐含什么增长假设？ | 当前行情、历史口径、同业口径 |
| 反证与风险 | 哪些事实会推翻受益逻辑？ | 澄清公告、减值、客户流失、政策变化 |

原包中的毛利率、ROE、PEG 等阈值属于经验提示，不是统一健康线。比较时必须保持行业、会计期、币种和一次性项目口径一致。

## 结论规则

- `SUPPORTED`：主营映射与落地证据均成立，财务传导没有明显冲突。
- `WATCH`：主营映射成立，但订单、产能或财务兑现仍需跟踪。
- `AVOID`：公告或财务存在明确反证，或受益逻辑只停留在概念层面。
- `INSUFFICIENT_EVIDENCE`：身份、占比、落地或最新财务任一关键层无法核验。

不得把 `SUPPORTED` 翻译成确定性“买入”。交易相关请求要转换为情景、触发条件、失效条件和风险预算。

## 输出模板

```text
【标的身份】代码 / 公司名 / 市场 / 币种 / 数据截止时间
【产业链位置】环节、产品或服务、上下游关系
【主营映射】业务名称、收入占比、来源和报告期
【落地证据】订单 / 产能 / 认证 / 客户 / 收入兑现
【财务传导】收入、利润、现金流、资本开支的同向或冲突
【反证】澄清、低占比、无订单、无产能或其他冲突
【结论】SUPPORTED / WATCH / AVOID / INSUFFICIENT_EVIDENCE
【跟踪项】需要更新的指标、日期和失效条件
```
