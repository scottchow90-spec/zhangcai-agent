# V6.4 数据容灾与 WorkBuddy 桥接规范

## 一、为什么必须改
V6.3 把 Python 运行时可以直接访问东方财富/腾讯当作隐含前提。一旦 WorkBuddy 沙箱、企业代理、DNS 或出口策略禁止脚本直连，整个系统会在正式计算前终止。这属于工作流架构缺陷，而不是“无候选”。

V6.4 保留 V6.3 四模型、行业六维、三态、13步生产门和历史防未来逻辑，不调整交易阈值；只重构数据入口与容灾机制。

## 二、双通道数据入口
1. **直连公共接口通道**：优先使用东方财富主源、腾讯独立二源。
2. **WorkBuddy 外部取数桥**：脚本直连失败时，返回 `DATA_BRIDGE_REQUIRED`（退出码4）并生成机器可读 `workbuddy_bridge_request.json`。这不是最终 BLOCKED。
3. WorkBuddy 收到退出码4后必须继续任务：使用其可用的浏览器、连接器、已授权行情服务或其他真实外部数据能力，构建 `workbuddy_data_bundle.zip`，随后自动以 `--data-bundle` 续跑。
4. 只有桥接后的关键数据仍不闭合，才允许最终标记 BLOCKED。

## 三、禁止伪降级
数据桥不得：
- 使用 synthetic/generated/mock/fixture 数据；
- 用当前值填补未知字段；
- 用同一提供商或同一底层行情流冒充主源与二源；
- 用当前行业成分回填历史正式样本；
- 用未来消息、未来K线、未来股票状态补历史；
- 把消息搜索失败解释成“无消息”。

## 四、桥接包 schema
根对象 `schema` 固定为：`a_share_quant_workbuddy_data_bundle_v1`。

必须包含：
- `mode`、`trade_date`、`generated_at`、`decision_asof`；
- `provenance.primary`；盘后还必须有与主源独立的 `provenance.secondary`；
- `universe` 全A快照；
- `histories` 股票未复权日K；
- `indices` 中的 `1.000001` 与 `0.399001`；
- `industries.stock_to_name`、`boards`、`board_bars`、`constituents`、`news`、`news_scan_complete`；
- 盘后 `secondary`；
- 盘中潜在候选所需 `intraday_trends`。

## 五、完整性与授权
数据桥只改变“数据如何进入引擎”，不降低任何数据门：
- 全A股票池不得低于配置中的最小完整性门；
- 主板历史覆盖率与宽度覆盖率仍执行原门槛；
- 行业精算缺关键数据仍传播 UNKNOWN；
- 盘后二源不可用/冲突仍阻断正式候选；
- 最终只有所有门闭合才能 AUTHORIZED。

## 六、WorkBuddy 强制行为
当执行出现：

`DATA_BRIDGE_REQUIRED`

WorkBuddy **禁止停止任务、禁止向用户汇报“网络原因无法执行”、禁止把它当最终结果**。必须读取生成的桥接请求，完成外部取数并自动续跑。只有在 WorkBuddy 本身不存在任何可用外部数据能力，或者外部数据无法满足完整性/独立二源门时，才允许最终报告 BLOCKED，并明确具体缺失字段与来源。
