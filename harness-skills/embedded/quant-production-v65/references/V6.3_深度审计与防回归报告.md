# V6.3 深度审计与防回归报告

本轮审计按用户固定三条红线执行：
1. 是否把已经修掉的早期错误重新带回来；
2. 是否偏离已经固化的完整工作流；
3. 是否通过简化输出、少跑步骤或静默删数据偷工减料。

## 一、发现并修复的问题
### A. 行业层不足
V6.2行业仅4条件，缺少多周期、行业内部扩散、时间持续、资金扩散、消息/政策/产业事件和生命周期。V6.3重构为六维100分，并增加过热/退潮与负面事件惩罚。

### B. 黄金点火盘中成交额硬门不一致
V6.2要求实时成交额字段存在，但黄金点火`model_ok`没有实际执行>=3000万元。V6.3已补齐，四模型实时量价硬门一致。

### C. 参数邻域稳定门配置存在但未执行
V6.2配置中有`min_neighbor_stability_ratio=0.75`，验证代码未真正计算。V6.3对冻结阈值相邻分数门及黄金点火相邻交叉窗口执行目标函数稳定性验证，并作为PRODUCTION_READY硬门。

### D. 双源一致率聚合错误
V6.2使用`bool(source_match)`，0.5也会被当成True。V6.3按每日数值比例0~1直接平均；0.5就是50%，不再伪装成100%。

### E. 第二行情源不可用仍可能正式授权
V6.3把最终候选二源不可用定义为价格核验UNKNOWN并BLOCKED，符合“未知不等于通过/不通过”的统一语义。

## 二、早期错误回归检查
以下均保留并增加自检：
- 行业缺失不送分；
- 平台缩量使用最近5日对更早15日，不把自身重复塞进20日均量；
- 60/120/250多尺度黄金支撑压力继续保留；
- 黄金点火不是只认当日交叉；
- 硬门不作为评分重复计权；
- 四模型标签独立保存；
- 盘中不线性外推全天成交量；
- 同日重复运行不复用旧未完成日K；
- 数分钟前稳定价不能用当前价代替；
- 前30分钟暖机继续保留；
- 历史实时无分钟快照禁止伪回放；
- BLOCKED禁止严格样本归档；
- UNKNOWN只在会影响结论时传播。

结论：本轮没有为了加入行业消息层而撤销上述已固化纠错。

## 三、工作流偏离审计
V6.3固化13步工作流，并要求每一步都进入`workflow_trace`。盘中不适用的二源收盘核验也必须记录“不适用”及原因，不能直接省略。BLOCKED下归档步骤必须记录“阻断未归档”，不能把没执行写成完成。

## 四、反偷工减料审计
输出从V6.2八段升级为十段，不是精简：新增“不可跳步工作流执行审计”和“行业六维强度、生命周期与消息驱动”。行业异常、消息检索异常、UNKNOWN、生产门失败全部保留输出；不允许只展示最终候选。

## 五、发布前强制命令
```
python -m compileall -q scripts tests
python scripts/workbuddy_entry.py selftest
python scripts/workbuddy_entry.py deep-audit
python scripts/workbuddy_entry.py offline-e2e
```

发布ZIP后必须再次解压，重复compile/verify/selftest/deep-audit/offline-e2e，并执行ZIP CRC测试。

## 六、本轮继续深挖后新增发现并已修复
### F. 行业硬门再次进入模型加分，构成重复计权风险
行业分既作为不同市场状态的准入硬门，又直接映射为0/1/2/4/5分，极弱市平台主升的“锁筹”也同时既是硬门又加5分。这会把已经满足的准入条件再次放大。V6.3最终版改为：行业硬门先独立执行，只有**超过当前市场行业门槛**的部分才形成“行业超额强度”增量分（每超过4分+1，最多+5）；极弱市平台主升中的锁筹只做硬门，不再重复加5分。

### G. 第13步工作流在预发布代码中被重复记录
预发布实现曾在构造payload前和真正写文件前各记录一次第13步，实际会形成14条trace；同时第六、七段实际标题与固定模板文字不完全一致。已删除重复记录，并把真实`execute`加入无网络端到端工作流测试：必须严格得到1~13且每步只出现一次；十段一级标题必须实际生成，不能只在模板文档里写着。

### H. 零样本参数邻域稳定率存在伪通过路径
继续审计发现，旧目标函数在`n=0`时仍会因为收益中位数的默认中心项得到0.1，可能让无样本参数邻域出现虚假的非零目标函数。最终版规定：`n<=0`目标函数强制为0；冻结点或相邻参数任一侧样本不足时，稳定率强制为0，不得用“没有证据”冒充“稳定”。

### I. 收益中位数正好为0时被truthiness误判为缺失
原门禁使用`ret5_median or -99`，真实中位收益=0会被当成缺失值-99，错误判失败。已改为显式`is not None`判定，0按真实0处理。

### J. 基准命中率存在跨年份信息泄漏
原生产验证把全部已成熟年份（含最终封存年份）的基准10日命中率作为滚动验证期间统一分母，会改变阈值选择目标函数中“相对基准提升”的权重。最终版已分离：验证年份只使用验证年份基准；开发样本外汇总只使用开发年份基准；最终封存只使用封存年份基准。最终封存/未来年份不再进入前序阈值选择。

### K. `min_train_samples`曾只写配置未真正执行
进一步静态审计发现`optimization.min_train_samples`存在于配置但没有进入滚动验证代码。这与“配置即规则”的要求冲突。最终版已在每个滚动窗口实际校验训练期核心样本数量；同时删除仅作说明却不被运行代码消费的行业描述型配置块，避免再次出现“看起来有配置、实际上没执行”。

### L. 严格事件归档后结果永不自动成熟
旧链条会把AUTHORIZED事件写入`event_archive.jsonl`，但`outcomes`始终为None，若不额外提供外部训练文件，内置生产验证永远无法形成成熟样本。最终版已在第11步加入历史样本成熟：按未来5/10个**市场交易日**自动补齐5日收盘收益、10日达到+10%、10日MFE/MAE；停牌日不借用未来复牌价。未成熟样本明确计数并禁止进入任何生产验收。

## 七、三条红线最终结论
1. **早期错误回归**：未发现仍未修复的回归；本轮反而抓出“行业硬门重复计分”等回归风险并已修掉。
2. **固化工作流偏离**：真实执行代码、`workflow_manifest.json`、SKILL和输出模板统一为13步；实际execute离线端到端测试验证13/13、无重复、无缺步。
3. **简化输出/少跑步骤**：固定十段输出不删节；盘中不适用项、BLOCKED归档、行业/消息异常、未成熟生产样本均必须显式显示。没有通过静默跳步得到“看起来完整”的结果。
