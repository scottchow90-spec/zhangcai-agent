# 黄金点火策略

## 适用范围

本技能只用于 **A股盘后短线强势股筛选与评分**。默认排除 ST、退市整理、北交所；不用于盘中追单、不用于港股/美股、不用于中长线基本面估值。

触发场景包括：
- “今天按V8实跑”“盘后选股”“多选一评分”
- “黄金点火”“平台突破”“龙回头”
- “用历史数据回测这个公式”“审计某条条件是否误杀强股”
- “给截图中的股票评分”

## 必须读取的资源

执行前按需读取：
- `@references/tongdaxin-v8.txt`：V8 通达信最终公式，规则源代码。
- `@references/data-schema.md`：行情字段、数据口径、缺失处理。
- `@references/decision-rules.md`：三模型解释、硬门槛、评分和互斥关系。
- `@references/regression-2026-09-11.md`：2026-09-11 回归锚点，用于检查工作流是否偏移。
- `@templates/result-template.md`：统一中文输出格式。

如本地有标准化 CSV，可优先运行：

```bash
python "${CLAUDE_SKILL_DIR}/scripts/run_v8.py" <日线CSV> --date YYYY-MM-DD --output-dir <输出目录>
```

脚本是确定性计算器，使用 Python 3 标准库，不依赖 pandas/numpy 等第三方包；若当前环境没有 Python，则不要静默安装依赖，改用可用的数据处理工具按同一公式计算。最终解释仍必须遵守本 SKILL.md 的数据门禁。

## 输入

用户可提供以下任一种输入：
1. 指定交易日，例如“按2026年9月11日实跑”。
2. 股票列表/截图/代码列表，要求逐只评分。
3. 本地 CSV 日线文件。
4. 要求全市场筛选，但未提供本地数据文件。

最低行情要求：每只股票目标日前至少 130 根有效日K；字段至少包含日期、股票代码、开、高、低、收、成交量，金额强烈建议提供。历史实跑还应尽力获得当日证券状态、板块归属、停牌/除权信息。

## 核心原则（不可省略）

1. **禁止猜测行情。** 开高低收、成交量、成交额、股票状态、板块归属任何一项拿不到，都不能编造。
2. **有数据必须获取。** 不能因为获取麻烦就把可获得字段标成“缺失”。先穷尽当前可用数据源，再判定缺失。
3. **缺失不等于0，也不等于通过。** 硬门槛字段缺失时，该股票只能标记“待核验”，不能列为“确认入选”。
4. **不强制选股。** 真实结果允许0只；但若0只，必须输出逐层淘汰统计和最接近门槛的候选，检查是否因数据缺失或某条规则异常误杀，禁止擅自降阈值。
5. **盘后只使用目标日收盘时已知的信息。** 禁止使用目标日之后的价格、公告结果或后视信息参与当日评分。
6. **三模型独立通过。** A/B/C 不互相借分；任一模型达到自己的硬门槛且评分≥70即可成为该模型信号。
7. **模型职责互斥优先解释。** 黄金点火抓第一次有效启动；龙回头抓强股洗盘后的二次启动；平台突破抓蓄势后的突破。已经明显点火多日的股票，不应再次解释成黄金点火。
8. **所有输出中文。** 不用英文状态名代替结论；F0/F1/F2如需展示，同时写明“当日金叉/次日首次确认/第二日首次确认”。

## 数据获取与核验流程

### 第一步：锁定目标交易日

把“今天/昨天”等相对日期解析成明确交易日，并在报告标题写绝对日期。确认该日为A股交易日；非交易日则使用用户明确要求的日期，不擅自换日。

### 第二步：建立候选池

全市场实跑时，不要只拿媒体列出的涨停股冒充全市场。优先使用完整A股日线库直接计算；若当前工具无法获得全市场完整日线，必须明确降级为“候选池实跑”，并说明候选池构造来源与覆盖范围。

候选池可先用宽松预筛提高效率，但不得改变最终模型：
- 目标日明显上涨、创近期高点、强势反包、或近期已有强势身份；
- 同时保留可能刚发生 EMA3/EMA21 金叉但涨幅尚未达到涨停的股票。

### 第三步：数据质量门禁

对每只股票检查：
- 目标日 OHLCV 是否完整；
- 目标日前是否至少130根有效日K；
- 是否混用了不同复权口径；
- 成交量单位是否一致；
- 成交额单位是否为元；
- 当日是否停牌/一字板/除权；
- 股票名称或状态是否存在 ST/退市；
- 是否北交所。

任何硬门槛依赖字段缺失，标为“待核验”。

### 第四步：运行 V8 三模型

以 `@references/tongdaxin-v8.txt` 为唯一规则源。若使用脚本，则运行 `scripts/run_v8.py`。

模型A：平台/蓄势突破。
- 结构项（四K重叠、波动收缩、量缩、靠近20日压力）主要评分化；
- 硬门槛保留趋势、突破、收阳、收盘质量、归一化强度、合理量比和不过热。

模型B：龙回头。
- 必须满足“历史强势在前 → 洗盘在后 → 当前再启动”；
- 洗盘窗口最多8个交易日；
- 不把已经完成启动后的继续加速重复认作第一次龙回头。

模型C：第一次有效黄金点火（重点）。
- EMA3 上穿 EMA21 只是事件，不是买点；
- 允许当日金叉、金叉后1日、金叉后2日第一次确认；
- 同一次金叉只允许第一次有效确认；
- 检查金叉前价格位置、EMA21斜率、金叉张口、短均线继续扩张、K线实体、收盘位置、突破、量比、跳空、10日过热、EMA20乖离和上方空间；
- 5日内不重复发黄金点火信号。

### 第五步：输出确认名单与近失名单

确认名单：硬门槛全部可核验且通过，评分≥70。

近失名单：评分接近70或只失败1个关键硬门槛。必须写明失败项，不能把近失名单和正式入选混在一起。

### 第六步：异常自审计

出现以下任一情况必须自动审计，不得直接交付：
- 全市场长期连续多日0信号；
- 单日信号异常暴增；
- 同一股票连续多日重复黄金点火；
- 当天明显已连续强势数日却被解释成“第一次黄金点火”；
- 评分≥70但关键硬门槛不成立；
- 数据源之间目标日收盘价/OHLC冲突。

处理方式：先核数据，再核计算，再核规则；**不得先改阈值迎合结果**。

## 黄金点火专用审计门禁

黄金点火必须逐项回答：
1. 金叉发生在哪一天？属于当日金叉、次日首次确认还是第二日首次确认？
2. 如果不是当日金叉，金叉当天/上一确认日是否已经满足有效确认？若是，则今天禁止重复发信号。
3. 金叉发生前一日相对EMA21的位置是否在允许区间？
4. 金叉前EMA21是否明显下滑？
5. 今天EMA3是否继续上升、EMA3-EMA21差值是否继续扩大？
6. 均线张口是否已经过大？
7. K线实体和收盘位置是否真实强，而不是高开低走？
8. 量比是否在0.75～3.50；若超限，必须明确是量能硬门槛失败，不能凭涨停补分。
9. 最近3日是否已有归一化强度≥0.70的高热日？
10. 10日累计涨幅与EMA20乖离是否过热？
11. 是否一字板？一字板不进入黄金点火。
12. 评分是否≥70，且5日内没有已确认黄金点火？

## 结果格式

使用 `@templates/result-template.md`。最少包含：
- 数据质量与覆盖范围；
- 正式入选；
- 三模型归属及评分；
- 黄金点火阶段；
- 关键通过项；
- 关键淘汰/近失原因；
- 若不是全市场完整日线，必须显著写“候选池实跑，不等于全市场扫描”。

## 生产纪律

- 禁止将媒体复盘名单直接当作模型输出。
- 禁止用“涨停”替代EMA交叉与评分计算。
- 禁止用未来几日走势反向证明当日应该入选。
- 禁止在缺乏回测证据时宣称“最优参数”“最高胜率”。
- 任何参数变更必须留下版本号并重新跑回归锚点。
- 用户要求“继续”“有下一步就做”时，完成计算、审计、修正和交付，不把计划当成结果。

## 2026-09-11 回归门禁

安装或修改本技能后，用 `@references/regression-2026-09-11.md` 做回归检查。回归结果不是硬编码名单，而是验证工作流没有退化：应能识别神宇股份、正和生态为黄金点火的重要基准案例；如数据源导致结果不同，必须逐字段列出差异，不能悄悄改结论。
