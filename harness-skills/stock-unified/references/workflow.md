## 固定执行链

1. 唯一公开入口是 `scripts/codex_entry.py`；禁止直接运行内部脚本。
2. 根入口把 `run` 唯一委托给内部统一验收执行器；内部脚本不是第二入口。
3. 执行器读取唯一权威股票技能目录，目录内容必须有效且不存在重复项。
4. 对目录中的每项技能定位根入口，禁止缺失入口，禁止根入口返回 `PROCEDURAL`。
5. 对目录内所有根入口运行 `selftest`；最多使用 8 路有界并发，但汇总顺序固定为权威目录顺序。任何非零退出或非 PASS 状态都使本轮验收失败。
6. 执行明细固定落盘到 `reports/executions/stock-unified-current.json`，随后重新解析、计算大小和 SHA-256。
7. 业务技能的完整业务实跑由全量股票业务矩阵逐项执行；本技能只负责统一目录、入口和验收口径，不临场选择业务脚本。

## 唯一命令

`python D:\C盘转移\日志\codex\skills\stock-unified\scripts\codex_entry.py run`

## 唯一验收

- `catalog_count` 等于唯一权威目录的当前条目数
- `entry_count == catalog_count`
- `selftest_pass == catalog_count`
- `procedural_entry_count == 0`
- 落盘 JSON 回读成功且当前 SHA-256 与输出一致

只要任一条件不满足，状态必须为 `BLOCKED`，不得降级为模板存在、文档存在或人工说明。

## 性能与准确性约束

- 同一业务工作流共享一把隔离锁，不同工作流不得被全局锁无条件串行化；排队上限为合同业务超时加 60 秒，且绝不超过 600 秒。
- 合同全局预检在排队前执行；非法动作、合同漂移、绑定哈希异常和进程控制风险必须在业务子进程启动前失败关闭。
- 连板日数据优先复用本批证据集，其次复用按交易日期生成的内容寻址缓存。可选源默认 8 秒超时并允许明确降级，必需源默认 45 秒超时且失败时阻断。
- 回执必须包含分阶段耗时、锁路径、实际等待时间、补充源模式与缓存命中状态，禁止把排队或外部抓取耗时混入不可解释的总耗时。
- 自检只验证合同、绑定与脚本语法，不得映射成真实业务运行或生成业务回执。

## 生产就绪工作流

1. 请求闸门先拒绝账户、凭据、经纪商、下单、撤单和自动交易参数，再校验参数数量、单项 64 KiB 与总计 1 MiB 上限。
2. 全局合同预检校验 53 项集合、顺序、入口、执行器、生产策略、共享运行时和业务文件哈希；发现变更即停止。
3. 同一工作流获取有界租约后，执行 TDX 只读安全扫描、证据准备和补充源准备；禁止启动、关闭、重启或控制通达信。
4. 业务子进程使用流式有界输出；总输出超过 16 MiB 立即终止本轮子进程。失败只能归为 `NONE`、`TIMEOUT`、`RESOURCE_LIMIT`、`SAFETY_VIOLATION`、`RUNTIME_ERROR` 或 `BUSINESS_REJECTED`。
5. 结果闸门要求唯一结构化业务对象、零返回码、未超时、空失败标记、有效业务绑定和工件映射。股票结论额外要求七维数据闸门及最新有效交易日一致。
6. 53 个适配器统一启用原子路径写入；业务后再次校验完整合同表面，原子写入 v4 回执并回读；交付时重新校验当前表面、请求指纹、日志、工件、数据闸门和 14 阶段遥测。
7. `readiness_validation` 只能证明工程就绪，不能作为股票结论；只有 `stock_conclusion` 且 `conclusion_eligible=true` 的当前干净回执才能授权结论。

生产控制矩阵每技能 19 项、全量 1007 项；任一项失败即为 `BLOCKED`。该标准不包含券商连接、订单 API 或实盘自动交易。
