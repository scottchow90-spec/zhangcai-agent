# A股热点舆情研判业务规范

## 1. 目标

输出一份统一 A 股热点舆情报告，回答市场宽度、热点方向、事件催化、板块反馈、涨停与晋级结构、成交额、参与者状态、反证风险和短线情绪。

## 2. 时间窗口

- 事件窗口：运行时刻向前滚动 72 小时。
- 市场验证窗口：最近三个完整交易日。
- 事件必须保留可核验发布时间和时间证据；只有榜单观察时刻、没有原帖发布时间的记录不得计入 10 条门槛。
- 市场验证事件不能充当 72 小时触发事实。

## 3. 八站强制合同

固定来源：

1. 淘股吧
2. 雪球
3. 微博
4. 知乎
5. 东方财富股吧
6. 韭研公社
7. 财联社
8. 金十数据

每站必须有至少 10 条有效高热 A 股舆情。有效记录至少包含：

| 字段 | 要求 |
|---|---|
| source | 固定中文来源名 |
| published_at | 可核验原帖或原文发布时间 |
| url | 独立来源地址 |
| event | 有价值且直接涉及 A 股热点、板块、资金或风险偏好 |
| heat_evidence | 排名、互动量、热榜、阅读量或其他可核验热度依据 |
| a_share_mapping | 对 A 股指数、板块、产业链、个股群体或情绪的直接映射 |

规则：

- 同一 URL 与规范化事件文本组成去重键。
- 热度必须是来源可解释的站内排名、互动量、阅读量或明确高热标识；`重要度0`、零互动伪高热和不可核验形容词无效。
- A 股映射必须在事件正文中找到指数、市场结构、板块、产业链或个股群体的语义落点；通用占位映射不能单独通过。
- `cleanCount` 必须等于实际清洗行数且不得超过 `rawCount + 本轮同任务补充数`；网页导航、登录、加载等残留不得进入有效记录。
- 不扩展 72 小时窗口，不跨站补足，不使用旧缓存补足。
- 任一站有效数量少于 10 条，整体 `BLOCKED`。
- 八站事件进入统一事件池和舆情分析，可参与主题发现、热度、分歧和短线情绪判断。
- 社区观点不能单独承担公告、政策、监管、订单、业绩、资产注入等强事实角色。

## 4. 三源五维市场验证

强制来源：

- 连板网
- 通达信
- 短线侠

强制维度：

| 维度 | 最低来源要求 |
|---|---|
| 热点 | 连板网、短线侠 |
| 板块 | 连板网、短线侠 |
| 涨停 | 三源中至少两源 |
| 晋级 | 三源中至少两源 |
| 成交额 | 通达信、短线侠 |

三源必须全部存在，且每个维度至少两源。连板网日期页、通达信本地闭市日数据、短线侠当前回合快照必须可追溯。任一缺失或过期即 `BLOCKED`。

## 5. 因果与证据

- 主题必须来自本轮事件原句，不读取预置具体板块池。
- 每条主线至少有触发事实、盘面确认、参与者确认，且来自不同事件。
- 每条主线至少覆盖 3 个来源和 3 个来源层。
- 正反证冲突时降低结论强度并标记分歧。
- 同一证据不得重复填入多行，不得从全池跨主题补来源。
- 强事实必须来自公告、政府监管、交易所、公司或权威财经原文。

## 6. 短线情绪

首页必须输出：

`短线情绪判断：强势/偏强/中性分化/偏弱/退潮。`

判断依据必须逐项结构化覆盖涨停家数、连板晋级、热点扩散或收缩、成交额、市场宽度，并输出置信度、冲突与反证。五维任一缺失或没有明确五级标签不得交付。

## 7. 产物与阻断

必须生成八站审计、三源交叉验证审计、采集审计、事件池、市场验证池、聚类、评分、红线审计、交付审计、Word 真实渲染审计和唯一 Word。渲染审计必须绑定报告哈希并证明 Word 打开、页数有效、PDF 导出、逐页图片一致、无空白页、无页底溢出及接触表存在。

以下任一情况整体 `BLOCKED`：

- 任一站少于 10 条；
- 记录缺发布时间、URL、热度依据或 A 股映射；
- 连板网、通达信、短线侠任一缺失；
- 任一市场维度不足两源；
- 市场宽度、因果链或证据唯一性硬闸失败；
- Word 缺明确短线情绪判断；
- 五维短线事实、置信度或冲突说明任一缺失；
- Word 真实渲染审计任一检查失败或报告哈希不一致；
- 尝试生成独立市场情报或独立三端社媒 Word。
