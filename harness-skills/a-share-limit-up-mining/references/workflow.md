# 连板挖掘统一工作流

## 模式路由

| 用户意图 | 模式 | 输出 |
|---|---|---|
| 每日连板龙头、盘后快筛、Top5 | `daily` | `candidate_pool.csv`、`dragon_score.csv`、`report.md`、`audit_log.md` |
| 连板龙头选股工作流、严格复算、证据研究 | `research` | 上述四件套 + `run_manifest.json` + 本地归档 |
| 连板挖掘、五步递进、精品/狙击、Word | `full` | 数据审计 + 分析 JSON + DOCX + G1-G17 与模板差异证据 |

未明确时使用 `full`，因为原“连板挖掘”是合并底座。

## 统一 13 步

1. `manual_gate`：显式手动确认；当日 15:05 前禁止正式结论；拒绝自动触发标记。
2. `source_preflight`：核验 ZTC、本地日线、涨停池、龙虎榜、研报、新闻、模板及输出目录。
3. `hard_exclusion`：剔除 ST/退市整理、北交所、科创板以及停牌、数据冲突和证据不足标的。
4. `mechanism_split`：10cm 与 20cm 分轨，分别使用 9.8% 与 19.8% 涨停阈值，不混排裸分。
5. `kline_verify`：严格模式核验 D、D-1 收盘涨幅达阈值且 `HIGH == CLOSE`；记录冲突、半日和停牌边界。
6. `pool_1`：形成真实二连板及以上候选池；本地 ZTC 只能参与交叉核验，不能替代板数证明。
7. `LHBFP`：使用与交易日绑定的龙虎榜资金证据；历史龙虎榜仅作带日期背景，不作当日加分。
8. `QSGFX`：分析梯队、封板质量、题材主线、同板块助攻、筹码和次日可执行性。
9. `QSYB`：收集与候选股票直接绑定且在有效窗口内的研报；禁止用泛行业文章冒充个股研报。
10. `RDXZ`：收集与候选股票直接绑定且在 72 小时窗口内的公告/新闻/催化；禁止泛市场标题充数。
11. `pool_2_score`：`daily` 用 5 维，`research/full` 用 8 因子；所有分项保留证据编号。
12. `risk_and_final`：执行风险 A-E 规则，得到精品、狙击、观察、剔除四类；阈值不足允许空结果。
13. `delivery_and_gate`：写出 CSV/JSON/Markdown；`full` 继续构建 DOCX 并通过 G1-G17、渲染与模板差异闸。

## 失败处理

- 主源失败后只能切换到能真实提供同等字段、同一交易日和可审计来源的备用源。
- 备用源不等价时，保持该字段缺失并修复源链；不得补零、默认二连板、降低阈值或伪造成功。
- 任一步失败后修复该步并从最近可验证断点重跑；禁止换技能、换报告或把错误说明当结果。

## 最终读回

- `daily`：确认候选均有真实连板数；5 维分项之和等于总分；Top5 只取总分不低于 70 的最多 5 只。
- `research`：除上项外，确认严格 K 线、8 因子、风险组合、`evidence_id` 和归档清单一致。
- `full`：除研究项外，确认 QSYB/RDXZ 为个股绑定证据，DOCX 标题/结构正确，G1-G17 全部通过。
