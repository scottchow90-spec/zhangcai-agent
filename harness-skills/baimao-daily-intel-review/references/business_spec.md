# 白猫老师每日资讯及复盘报告

## 用途

本技能把 `G:\白猫老师资料\白猫.txt` 中“白猫老师每日资讯+复盘报告”的要求固化为 Codex 可执行工作流，覆盖三类交付：

- 周一到周日每日早盘资讯：昨日盘后大事、核心监管异动、隔夜外盘、今日重要事项、简明观点，交付 Word/Markdown/JSON。
- 周一到周五 12:00 午盘异动推送：五大指数、市场情绪灯、涨跌幅前三板块、大盘股与微盘股风格，交付 Word/Markdown/JSON。
- 周一到周五 16:00 每日复盘报告：五大指数评分、涨跌家数与涨跌停、核心板块异动、9-15 点高热新闻、50 字总结和未来关注方向，交付 Word/Markdown/JSON。

本技能只做资讯复盘、研究分析和报告产物，不连接券商账户，不下单，不触碰任何真实交易。

本技能不是照抄模板。正式报告必须走“证据包 -> 数据闸 -> 事件池 -> 主题聚类 -> 盘面验证 -> 资金风格 -> 风险分层 -> 次日计划 -> 质量闸 -> Word 交付 -> 验收归档”执行链。没有证据包时只能生成 `DATA_REQUIRED` 准备单或 `collect-local` 本地证据草稿，不能生成正式市场结论。

## 优化完善层

原始文件只定义栏目和时间，本技能必须在原要求上补齐业务分析层，不得把原文复述为工作流。正式报告必须强制输出：

- 结论六件套：市场方向、最强主题、次强主题、主要风险、资金行为、下一窗口观察。
- 事件池：先聚合近期事件，再进入主题判断；不得从固定板块池直接套结论。
- 主题聚类：按事件强度、盘面验证、资金行为和风险折减排序。
- 市场反馈验证：用指数、宽度、板块、涨停结构、成交和风险偏好验证事件。
- 资金与风格行为：比较沪深300、微盘指数、防御方向和成长方向。
- 风险分层与次日计划：每个方向给触发条件、失效条件和降级条件。

## 科学工作流硬闸（2026-06-28）

本技能属于 A股、股票、复盘、市场情报、新闻、公告、政策、指数、板块、热点、涨停、连板、资金、主力、机构、游资、龙虎榜、技术分析、K线、支撑、压力、通达信、TDX 场景。必须执行“数据 -> 宏观 -> 微观 -> 消息政策 -> 技术 -> 资金 -> 结论 -> 风险 -> 产物 -> 验收”闭环。

- 数据：指数、成交、涨跌家数、涨跌停、连板、板块、新闻、公告、监管、IPO、隔夜外盘必须有来源和时间。
- 宏观：上证、深证、创业、科创、北证、沪深300、微盘指数必须标注交易日与窗口。
- 微观：大涨停牌、重要减持、个股异动、产业链事件必须区分事实和推断。
- 消息政策：新闻、公告、政策、事实、观点、传闻、舆情必须分层，传闻不得作为强结论。
- 技术：涨停、连板、炸板、趋势、量价、K线、支撑、压力只作为市场结构证据。
- 资金：主力、龙虎榜、机构、游资、散户和资金流必须说明字段来源。
- 结论：评分、排序、过滤、剔除、Top 热点必须由数据链、事件池、主题聚类和盘面反馈共同支持。
- 风险：给出风险、失效、降级、排除条件；风险分层和次日计划缺失时必须 BLOCKED。
- 产物：报告固定输出到本技能 `reports\generated` 或 `reports\workflow_acceptance`，正式交付必须包含 `.docx` Word 文档，同时保留 `.md` 和 `.json` 证据。`DATA_REQUIRED` 准备单不得当作正式报告。

## 失败处置

任一数据门、脚本入口、报告模板、硬闸、验收脚本失败，均返回 `BLOCKED`。不得把模板、计划、问题说明、空白报告或未经核验的市场判断包装成正式复盘结论。

若证据不足，执行结果必须包含具体缺失字段，例如 `indices 缺少 上证`、`news 数量不足`、`sources 缺失`，并写入 `reports\quality` 下的阻断 JSON。

## 执行链总览

本工作流不是模板搬运，必须按以下闭环执行：

1. `collect-local`：读取本地 `tdx-local-hub` 状态、板块清单、新闻缓存，生成证据草稿。
2. 人工或上游数据接口补齐证据包：字段必须符合 `references\evidence-schema.json`，并包含事件池、主题聚类、盘面验证、资金风格、风险分层和下一窗口计划。
3. `run --evidence`：读取证据包，执行数据门、结论六件套、指数评分、情绪灯、板块排序、新闻热度筛选、主题评分、风格判断和风险失效生成。
4. 产物生成：输出 `.docx` Word 正式报告，同时输出 `.md` 和 `.json` 证据报告；Word 必须包含新增业务模块。
5. `quality-gate`：检查 Word 可读、核心结论、证据表、事件池、主题聚类、盘面验证、资金风格、风险分层、次日计划、无 `DATA_REQUIRED` 残留、非测试证据冒充正式报告。
6. `auto`/closure gate：验证 schema、证据阻断、证据驱动报告、质量闸和两个 Codex 硬闸。

`generate` 只生成 `DATA_REQUIRED` 数据准备单，不能作为正式复盘报告。

## 优化业务链

1. 结论先行：报告开头给市场方向、最强主题、次强主题、主要风险、资金行为和下一窗口观察。
2. 事件池：从官方公告、监管、主流财经媒体、交易复盘、本地新闻缓存、机构观点、韭研公社热度文章、短线交易社区、零售讨论和海外映射中建立近期事件池；韭研内容只作题材线索和观点样本，强事实必须回查官方原文。
3. 主题聚类：按关键词、产业链、政策事件、盘面反馈和资金风格聚类，计算主题分。
4. 市场反馈验证：用指数、涨跌家数、板块涨跌、涨停/跌停/连板、成交和风险偏好验证主题。
5. 资金风格：比较沪深300、微盘指数、进攻方向和防御方向，说明资金正在进攻、轮动、防御或兑现。
6. 风险分层：列出数据、事件、交易结构和外部扰动风险，给触发条件和失效条件。
7. 下一窗口计划：早盘给开盘观察，午盘给午后观察，收盘给次日观察。

## 输入与数据源

本工作流输入分为四类：

- 行情结构：五大指数、沪深300、微盘指数、成交额、上涨家数、下跌家数、涨停、跌停、连板、板块涨跌幅。优先 `C:\new_tdx_mock` 和 `tdx-local-hub`。
- 新闻公告：9-15 点市场新闻、昨日盘后大事、韭研公社热度文章、公告、监管、停牌、减持、产业政策、海外市场异动。必须记录来源、发布时间、抓取时间和热度依据；韭研内容只作热点与题材线索。
- 交易日历：新股打新、新股上市、重要日程。必须区分交易日和自然日。
- 外盘信息：美股指数与主要板块。只有指数或核心板块波动超过 1% 时，才写入隔夜外盘异动模块。
- 业务分析字段：结论六件套、事件池、主题聚类、市场反馈、资金行为、风险分层和下一窗口计划。字段要求见 `business-blueprint.md`、`data-source-matrix.json` 和 `scoring-model.json`。

禁止无来源写入具体数字。当前资讯和复盘必须检查最新有效交易日；若本地行情或新闻缓存过期，返回 `DATA_STALE` 或 `DATA_BLOCKED`。

## 早盘资讯流程

时间规则：周一到周日每日早上执行；源文件未给出具体小时，调度时必须由用户或自动化配置明确运行时点。

模块顺序固定：

1. 昨日盘后大事：采集各大网站头条和韭研公社热度文章，按重复率和市场影响筛出 1-2 条，不得只取单一来源；涉及公告、政策、监管、订单或业绩的内容必须回查官方原文。
2. 核心异动监管：停牌、监管问询、重要减持、重大风险公告、大涨个股异常。
3. 隔夜外盘：主要看美股。若指数或核心板块涨跌超过 1%，列出涨跌幅较大的板块和原因；不足阈值时只写“未触发外盘异动阈值”并附来源。
4. 今日重要事项：新股打新、新股上市、重要会议、关键公告生效。
5. 简明观点：只基于上面事实给 3-5 条短观点，不给买卖指令。

输出产物：`reports\generated\<date>\morning_<timestamp>.docx`、同名 Markdown 与 JSON。Word 文档是正式交付文件，Markdown/JSON 是可追溯证据。

## 午盘异动流程

时间规则：周一到周五 12:00。

模块顺序固定：

1. 五大指数：上证、深证、创业、科创、北证。上证波动超过 1%，创业或科创波动超过 2% 时必须解释原因。
2. 市场情绪灯：上涨家数占比大于等于 65% 为绿灯，35%-65% 为黄灯，低于 35% 为红灯。
3. 核心板块异动：列涨幅前三、跌幅前三，并说明市场风格和上涨板块异动原因。
4. 市场格局：比较沪深300与微盘指数，判断大盘股和微盘股偏好。

输出产物：`reports\generated\<date>\midday_<timestamp>.docx`、同名 Markdown 与 JSON。Word 文档是正式交付文件，Markdown/JSON 是可追溯证据。

## 收盘复盘流程

时间规则：周一到周五 16:00。

模块顺序固定：

1. 五大指数：上证、深证、创业、科创、北证；标出上涨最多和下跌最多的指数，给红灯/绿灯和评分。
2. 市场情绪：涨跌家数、涨跌比、涨停家数、跌停家数、连板家数。
3. 核心板块异动：涨幅前三、跌幅前三，评论市场风格和上涨板块原因。
4. 今日大事：复盘 9-15 点市场新闻，按热度抓取 2-3 条并分析原因。
5. 综合分析：约 50 字总结今日市场，列未来几日重点关注方向 2-3 个。

输出产物：`reports\generated\<date>\closing_<timestamp>.docx`、同名 Markdown 与 JSON。Word 文档是正式交付文件，Markdown/JSON 是可追溯证据。

## 数据 -> 宏观 -> 微观 -> 消息政策 -> 技术 -> 资金 -> 结论 -> 风险 -> 产物 -> 验收

1. 数据：先取得行情、指数、成交、涨跌家数、涨跌停、连板、板块、新闻、公告、监管、IPO、隔夜外盘的来源证据。
2. 宏观：判断指数、成交、市场宽度、风险偏好和大盘环境。
3. 微观：核对公告、停牌、减持、产业链事件、个股异动和板块兑现条件。
4. 消息政策：区分新闻、公告、政策、事实、观点、传闻和舆情。
5. 技术：只把涨停、连板、炸板、趋势、量价、K线、支撑、压力作为结构证据。
6. 资金：核对主力资金、龙虎榜、机构、游资、散户和资金流是否同向。
7. 结论：输出评分、排序、过滤、剔除、Top 热点前必须能回指到数据证据。
8. 风险：说明数据延迟、消息证伪、板块退潮、指数失守、流动性下降等风险和失效条件。
9. 产物：生成 Word 文档、Markdown 与 JSON，路径写入验收报告。

## 失败处置

- 行情数据缺失：返回 `DATA_BLOCKED`，不输出指数评分。
- 当日数据过期：返回 `DATA_STALE`，不输出“今日”结论。
- 新闻来源不足：返回 `NEWS_SOURCE_BLOCKED`，不输出热点排序。
- 外盘来源不足：早盘外盘模块降级，但必须说明缺失项。
- 硬闸失败：返回 `BLOCKED`，显示失败脚本、失败 gate、恢复动作。
