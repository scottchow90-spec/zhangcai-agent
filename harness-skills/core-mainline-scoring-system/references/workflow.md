# 核心主线评分工作流

1. 权威股票路由必须唯一返回本技能。
2. 规范运行时先获取当日连板网快照；业务适配器再刷新短线侠六项数据集和最近至少两个可用交易日的连板网历史快照。
3. 评分器读取本地通达信板块成分与日线成交额，标准化题材名并按股票代码去重；通达信根目录固定为 `C:\new_tdx_mock`，目标日线记录日期必须与本轮有效交易日一致，并在板块证据中保存前后交易日、源路径和文件哈希。
   最近交易日连板网页面的逐股题材/理由只可补个股正宗度，且必须保留 `CLEAN_PASS`、交易日和原页 URL；不得据此回填当前梯队角色、当前涨停状态、板块成员评分、主营核验或公告核验。
4. 解析短线侠涨停池的封单额、开板次数、首次/最终封板时刻和当日成交额；使用短线侠与连板网逐股代码交集验证本轮数据属于同一交易会话，覆盖低于80%必须阻断收盘确认。
5. 对每个板块形成九项原始分，再执行精确3/2/1板与成分股数量两道硬门槛。
6. 对通过原始层的板块执行收盘确认：先检查原始分、排名、涨停占比、样本数量和覆盖，再把早封率、零开板率、尾盘回封率、封单额/成交额逐项与同日市场基线比较；至少两项相对质量信号通过才可入选。
7. 对收盘确认后的前两名执行歧义检查；质量信号数相同且原始分差不超过5分时输出 `AMBIGUOUS_CLOSE`，不得强行指定唯一主线。
8. 输出结果级目标交易日、全局会话一致性，以及全部板块的原始分、决策分、星级、证据缺失项、门槛失败项、收盘确认项、九项明细和来源状态。
9. 无任何板块通过收盘确认时输出 `NO_CONFIRMED_MAINLINE`；没有可评分板块或关键输入不可读才是 `DATA_REQUIRED`。
10. 请求8K海报时，业务适配器必须使用同次评分结果和同次连板网快照生成候选图；候选图通过内容、字号、边界、重叠、尺寸和浅色背景硬闸后才可复制到正式交付目录。

固定产物：`core-mainline-result.json`、`business_result.json`、子进程标准输出和标准错误。结论与产物必须绑定同一规范回执后才能交付。
