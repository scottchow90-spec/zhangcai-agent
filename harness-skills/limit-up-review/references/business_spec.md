## 1. 业务目标

本技能不是涨停名单汇总器。它必须把当日证据组织成可复核的决策支持，明确回答：

1. 今天的涨停结构发生了什么，处于怎样的历史位置？
2. 哪些方向形成了可论证的一致性，哪些只是数量堆积或偶然聚集？
3. 官方涨停池内各股票承担什么角色，为什么值得观察或应当排除？
4. 每个判断由什么证据支持，最强反证是什么，何时失效？
5. 次日若加强、轮动、失败或受外生冲击，应观察什么、如何降级和规避什么？
6. 昨日判断实际表现如何，哪些规则需要降权、停用或继续积累样本？

输出必须分开事实、推断、假设、风险和未验证项，不承诺收益，不提供无条件买卖指令。

## 2. 宇宙模型

### 2.1 候选宇宙

- 目标交易日的官方涨停池是唯一原始候选宇宙，原始集合、行数、来源和哈希必须完整保留。
- 名称带退市整理或退市标识的股票执行硬剔除；剔除代码、名称、原因和规则必须进入本轮审计，且原始池减去剔除集合必须与可交付池完全一致。
- 全量可交付事实表必须与退市硬剔除后的官方合规池代码集合、行数和唯一性完全一致。
- 重点观察池和所有个股结论只能是官方合规池的子集；退市股不得进入统计、方向映射、观察池、公式样本、CSV、Markdown 或 Word。
- 官方涨停池缺失、为空、关键字段缺失或集合无法确认时，任务直接 `BLOCKED`。
- 禁止用本地块、强势股池、缓存、历史名单、阈值猜测或人工名单补充候选。

### 2.2 分析与对照宇宙

以下数据可以用于解释市场、构建基线和形成反证，但不能新增候选：

- 全 A 市场、主要指数、行业和概念；
- 炸板、跌停、未涨停同题材样本；
- 历史涨停池、历史行情和历史复盘结果；
- 公告、政策、新闻、监管信息和其他有时间戳的催化证据。

报告必须区分“候选宇宙”和“分析/对照宇宙”，不得把对照样本写成观察候选。

## 3. 时间与证据合同

每轮执行必须锁定：

- `run_id`
- `target_trade_date`
- `as_of`
- `timezone`
- `latest_completed_trade_date`
- 数据采集时间和数据所属时间

每条证据必须包含：

- `evidence_id`
- `source_name` 与可追溯定位
- `observed_at` 与 `data_time`
- 字段口径、值、单位和适用对象
- 内容哈希或等价完整性标识
- 事实/观点/传闻层级

所有可见推断必须引用 `evidence_records` 中的稳定 `evidence_id`。个股证据必须保存代码、字段、实采值、观察时间和来源；聚合指标不能代替个股字段证据。

来源时间晚于 `as_of` 的数据不得参与本轮推断。传闻和无来源观点不能支持强结论；来源冲突必须保留冲突双方及采用理由。

## 4. 数据域与最低分析覆盖

### 4.1 市场环境

至少覆盖指数表现、成交额及其变化、上涨/下跌家数、涨停/炸板/跌停、市场宽度和相对历史基线。仅有涨停家数不能定义市场强弱。

### 4.2 涨停结构

至少覆盖首板、二板、三板及以上梯队，最高板，晋级与断层，首次封板、开板回封、封板质量、量价和亏钱效应。结构判断必须同时讨论正向证据和脆弱点。

### 4.3 方向映射

方向可由行业、概念、产业链、事件催化等标签共同形成，但必须保留映射依据。不能把“所属行业”字段直接当作完整方向逻辑，也不能为了形成主线而人工合并无共同语义的样本。

### 4.4 催化与基本事实

公告、业绩、订单、政策、产业事件和新闻必须标明发布时间、事实层级和与方向的语义关联。催化缺失时写 `UNAVAILABLE`，不得用价格上涨反推存在催化。

### 4.5 资金与量价

资金流、龙虎榜、机构、游资、成交、换手、封单和量价关系只能按真实覆盖度使用。资金字段缺失不能填零；单一资金流不能独立推出方向持续性。

### 4.6 历史与复核

至少尝试构建 20/60 个交易日同口径基线，并读取上一轮冻结预测账本。样本量、覆盖窗口和口径变化必须进入质量矩阵。

## 5. 质量与缺失模型

`business_result.json` 必须包含 `data_quality` 与 `data_gaps`：

- 各数据域的新鲜度、覆盖率、冲突、异常和可追溯率；
- 缺失字段、缺失原因、影响的 claim 和置信度上限；
- 历史窗口的实际样本量与口径一致性；
- 采用或放弃冲突来源的理由。

统一规则：

1. 缺失值写 `UNAVAILABLE`，绝不写成 `0`。
2. 零必须有来源明确证明其数值确实为零。
3. 关键域缺失必须降低置信度；缺失使判断无法成立时，状态必须是 `INSUFFICIENT`。
4. 官方候选集合、交易日、关键标识或证据时点不可验证时，必须 `BLOCKED`。
5. 不得因交付压力把缺口改写成中性套话或兜底判断。

## 6. 历史基线模型

每个重要市场或方向指标应提供：

- 当前绝对值；
- 20/60 日样本量；
- 历史分位或相对基线偏离；
- 同口径趋势与结构变化；
- 基线是否可用及其限制。

基线至少覆盖市场宽度、涨停数、炸板率、跌停数、最高板、连板晋级率、方向集中度、成交和资金覆盖。窗口不足时不得用固定阈值、经验印象或未校准分数替代。

## 7. 市场结构对象

`market_regime` 不是一句标签，必须包含：

- 结构结论与结论状态；
- 关键支持证据；
- 最强反证和内部背离；
- 相对 20/60 日基线的位置；
- 置信度、置信度依据；
- 适用边界与失效条件；
- 对次日观察优先级和风险暴露的影响。

若宽度改善但炸板率、跌停或高位亏钱效应恶化，必须保留这种分歧，禁止压缩成“强”或“弱”的固定判断。

## 8. 方向 Thesis Card

每个进入核心讨论的方向都必须形成 thesis card：

| 字段 | 业务含义 |
|---|---|
| `direction_id` / `label` | 稳定标识和可读名称 |
| `member_mapping` | 官方涨停池样本及映射依据 |
| `breadth` | 广度及相对基线 |
| `continuity` | 连续性、晋级和梯队 |
| `height_and_quality` | 高度、封板和量价质量 |
| `catalyst` | 有时间戳的催化事实或 `UNAVAILABLE` |
| `capital_consistency` | 资金一致性及覆盖度 |
| `counter_evidence` | 炸板、跌停、分化、资金背离等反证 |
| `status` | 论证状态 |
| `confidence` | 置信度及依据 |
| `invalidation` | 次日可观察的失效条件 |

“核心方向”至少需要广度、连续性、封板质量、催化可信度、资金一致性五维中的三维共同支持，并且连续性与催化可信度不可缺失。未满足时只能标记“待确认”或 `INSUFFICIENT`，不能使用主线、最强、发酵、高潮等固定词替代论证。

## 9. 个股角色卡

个股分析先确定角色，再讨论优先级。允许的标准角色包括：

- 高度锚；
- 方向核心；
- 容量承接；
- 首板确认；
- 补涨跟随；
- 孤立涨停；
- 脆弱样本。

每张角色卡至少包含：

- 代码、名称、所属方向和角色；
- “为什么是这个角色”的字段证据；
- “为什么现在观察”的时点逻辑；
- 至少三个独立证据维度；
- 最强反证、确认条件、排除条件和失效条件；
- 与同方向样本的横截面对比；
- 观察优先级和置信度依据。

证据不足的股票可以保留在全量事实表，但不得进入重点观察结论。观察优先级不是买入建议。

## 10. Claim Graph

`business_result.json.theses` 是 Claim Graph 的机器字段，也是所有可见分析结论的来源。节点类型：

- `FACT`：直接来自有时间戳证据的事实；
- `INFERENCE`：由多个事实推导的解释；
- `HYPOTHESIS`：等待次日验证的条件化假设。

每个非事实 claim 必须包含：

- `claim_id`、对象和陈述；
- 引用的 `evidence_id`；
- 至少两个独立证据维度；
- 推理路径；
- 最强反证；
- `confidence` 与依据；
- `invalidation`；
- `practical_implication`，即条件成立时的实战观察与降级动作；
- 结论状态。

`claim_type` 只能是 `INFERENCE` 或 `HYPOTHESIS`；`reasoning_path` 至少记录两个从事实到推断的步骤；`confidence_basis` 必须同时说明支持维度、限制因素和历史基线状态。反证必须显式标为 `CHALLENGES`，写明替代解释，不能用继续支持原结论的语句冒充反证。

结论状态只允许：

- `SUPPORTED`
- `CONTESTED`
- `INSUFFICIENT`
- `REJECTED`

因果 claim 必须同时满足：

1. 事件发生在价格反应之前；
2. 事件与方向或公司的语义映射清晰；
3. 存在跨样本或横截面响应；
4. 已检查市场普涨、情绪共振等替代解释。

不满足时只能写相关关系或假设，不能写成“因为……所以必然……”。

## 11. 置信度与评分规则

置信度必须来自证据质量，不得来自措辞强度：

- `HIGH`：关键域无缺口，至少三个独立维度同向，历史基线可用，最强反证不足以推翻，且失效条件明确。
- `MEDIUM`：至少两个独立维度支持，但存在非致命缺口、反证或样本限制。
- `LOW`：证据有限、冲突明显或关键域缺失，只能作为待验证假设。
- 无法达到 `LOW` 的判断必须是 `INSUFFICIENT` 或 `REJECTED`，不得可见化为方向结论。

分数、权重和阈值只有在冻结定义、足够历史样本、前向验证和稳定性检查完成后，才能解释其校准意义。未校准分数只能用于内部排序，不能：

- 单独决定方向结论或观察池；
- 出现在可见摘要中充当证据；
- 被表述为胜率、概率或确定性强弱；
- 掩盖缺失字段。

## 12. 四分支情景树

次日计划必须包含：

- `STRENGTHEN`：主方向加强；
- `ROTATION`：方向轮动或高低切换；
- `FAILURE`：核心断板、结构走弱或亏钱效应扩散；
- `EXOGENOUS_SHOCK`：公告、政策、海外或突发事件改变原假设。

每个情景至少包含：

- 盘前、开盘、盘中、收盘观察点；
- 两个可观察触发器；
- 涉及的方向和角色；
- 条件化行动/回避原则；
- 对应风险、失效条件和需要降级的 claim。

在概率模型完成历史校准前，不得给情景分支配置概率。情景树的价值是提前定义“看见什么就如何调整”，不是事后解释。

## 13. 冻结预测账本

渲染前必须冻结 `prediction_ledger`，至少记录：

- `run_id`、`as_of`、冻结时间和内容哈希；
- 预测对象、观察期限和对应 claim；
- 前提条件、预期可观察结果；
- 确认、失效和排除条件；
- 对应情景分支与风险边界。

账本必须有一条覆盖每个 thesis、每个观察对象的前向条目。每条条目包含对象、期限、关联 claim、前提、可观察预期、确认条件、失效条件、情景链接和风险边界；哈希必须覆盖这些条目本身。

冻结后不得覆盖原记录。任何修订必须新增版本并保留原哈希，从而阻止用次日结果倒改昨日判断。

## 14. business_result.json 领域合同

渲染前的唯一分析真相源至少包含：

- `schema_version: "limit-up-review.business-result.v9"`
- `run`
- `official_universe`
- `sources`
- `metrics`
- `evidence_records`
- `domains`
- `theses`（Claim Graph）
- `scenario_tree`
- `watchlist`
- `prediction_ledger`（冻结预测账本）
- `blocks_delivery`
- `blocks`
- `unverified_items`
- `validation`

其中 `official_universe` 必须同时保存原始官方数量、退市硬剔除规则、剔除明细、合规代码集合与数量；原始数量减去剔除数量必须等于合规数量。

可见 Markdown、观察池和 Word 只能从该文件映射，不得在渲染阶段新增、升级或改写结论。CSV 保存官方候选宇宙的完整事实明细，不等同于分析结论。

## 15. 业务语义硬闸

以下任一情况直接 `BLOCKED`：

1. 官方候选池缺失、为空、集合不一致、重复或被外部名单扩充。
2. 目标交易日、`as_of`、来源时间或关键证据不可追溯。
3. `UNAVAILABLE` 被替换为零，或零没有事实来源。
4. 关键方向/市场结论没有历史基线、独立证据、最强反证、置信度依据或失效条件。
5. 因果结论未满足时间先后、语义映射、横截面响应和替代解释检查。
6. 重点观察对象不在官方涨停池，或缺角色、三维证据、确认/排除/失效条件。
7. 四分支情景树不完整，或使用未经校准的概率。
8. 冻结预测账本缺失、未哈希或被覆盖。
9. 未校准分数直接生成可见结论。
10. 分析结果含模板默认结论、固定措辞、无证据兜底判断。
11. 渲染器产生了 `business_result.json` 中不存在的 claim、候选或情景。
12. 本轮产物、证据和哈希不属于同一 `run_id`。
13. 原始官方池、退市硬剔除记录和可交付池差集不一致，或可见产物出现任何被剔除的退市代码/名称。
14. 可见 Markdown 或 Word 出现拉丁字母；机器状态、情景键、公式字段和行业缩写必须先映射为中文。

`INSUFFICIENT` 不是失败伪装：它允许诚实保留事实，但不得把证据不足的对象升级为重点方向或重点观察结论。

## 16. T+1 / T+N 复核与校准

复核必须从冻结账本开始，至少记录：

- T+1/T+2/T+3 的方向延续、连板晋级和相对基准表现；
- 观察对象的最大有利偏移与最大不利偏移（MFE/MAE）；
- 触发器、确认条件、失效条件和情景分支是否命中；
- 风险提示的召回、误报和漏报；
- 方向 thesis、角色判断和排序规则的稳定性；
- 规则需要保留、降权、停用或增加样本的原因。

禁止用结果改写原预测。只有在定义冻结、样本充分、前向验证通过且稳定性可复现后，分数或概率才可以从“未校准”升级。

## 17. 渲染边界

模板和 Word 只负责呈现，不承担分析。渲染器必须：

- 原样保留结论状态、反证、置信度依据、失效条件和数据缺口；
- 不补写默认结论、固定周期词或兜底判断；
- 不把 `CONTESTED` / `INSUFFICIENT` 改写为确定性表达；
- 不把全量名单堆砌当作深度分析；
- 不暴露后台路径、调试过程或验收日志到业务正文。
- 不显示拉丁字母，不显示被退市硬剔除的代码或名称；所有内部状态、情景键和公式字段必须使用固定中文显示名。

分析深度由证据链、反证、历史基线、情景树和可复核预测产生，不由篇幅、章节数量或视觉包装产生。
