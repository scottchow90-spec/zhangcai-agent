# 龙虎榜分析

## 固定入口

先用股票统一路由处理用户原话，只执行路由返回的本技能固定入口：

```powershell
python D:\C盘转移\日志\codex\scripts\stock_canonical_runtime.py route --query "<用户原话>"
python D:\C盘转移\日志\codex\skills\a-share-longhubang-analysis\scripts\codex_entry.py run -- --date YYYY-MM-DD
```

严禁直接执行 `legacy_codex_entry.py` 或 `longhubang_workflow.py` 代替业务入口。需要同时交付结论和已检查海报时，按 `references/workflow.md` 的两阶段海报流程执行，最后使用 `complete --artifact-relative`。

## 业务规则

- 未指定日期时解析最新可用交易日；指定日期时不得改成其他日期。
- 默认筛选龙虎榜净买额严格大于5000万元。
- 只保留A股股票，排除可转债；同股多条上榜原因保留净买额最高记录。
- 保留三日累计上榜标记。
- 每股输出股票名称、代码、净买额、代表席位、公开游资归属、核心概念板块，并扫描该股全部买卖席位，不能只检查净额最大的席位。
- 游资归属先以完整规范化营业部名称精确核对本机公开游资档案和本次重新抓取的连板网公开席位页；禁止用局部地址、相似券商名或模糊包含关系误配。没有精确命中的营业部写明“普通营业部（公开游资名录无精确匹配）”；机构专用与沪深股通写明席位性质，不冒充游资。
- 核心概念逐股重新抓取东方财富精确题材标签，短线侠与连板网只作交叉证据。精确题材取不到时阻断，不生成占位词。
- 东方财富是龙虎榜金额和席位主源；短线侠、连板网只作热点、题材和情绪补充交叉验证，失败时记录降级但不伪造数据。

## 结论优先硬规则

- 分析必须先输出结论，再输出逐股证据；只列股票、金额、席位或概念表格一律阻断。
- 结论必须同时覆盖：资金集中度、大资金主攻方向、代表席位风格、主板/成长板风格、三日持续性、上榜触发风格和证据边界。
- 每个结论必须绑定至少一个可复算指标，并明确置信度与限制条件；禁止用“按净买额降序展示”等同义反复冒充结论。
- 多题材股票的净买额在可靠题材标签间等额分摊，避免同一笔净买额被重复统计；同时披露题材识别覆盖率。
- 席位结构按每股代表席位类型对应的标的净买额归类，只能描述样本风格，严禁表述为该席位贡献了全部股票净买额。
- 公开游资名录无精确匹配、补充源降级和单日样本限制必须用事实和数量进入风险边界，不得隐藏。
- 分析、报告和海报严禁出现“未识别”“未可靠识别”“其他主题”“默认结论”“固定措辞”“兜底判断”等占位或模板结论；验证器必须将其视为硬失败。

## 数据源

实时运行必须在当前任务重新抓取东方财富龙虎榜及席位、短线侠共享接口和连板网指定日期开放数据。短线侠不得读取浏览器凭据；连板网需注明原日期页和 CC BY 4.0。

## 海报硬门槛

- 横版8K固定为 `7680x4320`；背景必须明亮。
- 所有可见文字原图至少160px，核心正文至少228px，标题至少320px，主要金额至少242px。
- `1080x608` 完整预览分别对应至少22px、32px、45px、34px，是主要可读性验收面；所有渲染行最多22字。
- 单张放不下就分页，严禁截断股票、缩小字号或制造重叠。
- 两页海报必须合计完整呈现七类结论和全部入选股票；每条海报结论包含方向与量化证据，不得退化成数据表标题。
- 海报候选、检查记录和交付工件必须绑定同一份结构化结论哈希；缺少结论、证据或任一结论维度时阻断。
- 候选图必须先通过亮背景和可读性代码硬闸，然后人工查看完整预览并记录检查结果；只有记录与候选哈希一致时才能进入 `artifacts` 交付目录。

具体命令、离线复现参数和验收顺序见 `references/workflow.md`。
