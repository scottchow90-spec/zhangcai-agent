# 风险排雷技能

桌面端执行路径必须从 `STOCK_SKILLS_ROOT` 定位本技能，从 `ZHANGCAI_TDX_ROOT` 定位通达信；旧示例中的开发机 D 盘路径不适用于安装包。

## 核心边界

- 本技能是“风险排雷”和“风险预警”的唯一整合入口；“风险预警”只保留为兼容名称，不再对应独立技能。
- 同一次运行必须同时完成个股证据排雷和市场与技术风险叠加，不得把其中一项省略后声称完成。
- 只使用本轮新抓取并实际返回的数据。旧目录、旧名单和历史报告只能用于追溯，不能作为当前结论。
- 只提供研究和风险控制支持，不自动下单，不保证收益。

## 唯一执行入口

所有业务运行只允许进入：

```powershell
python "%STOCK_SKILLS_ROOT%\risk-mine-clearance\scripts\codex_entry.py" run
```

需要指定日期、深挖数量或人工传闻文件时，在 `run --` 后传入 `--date`、`--deep-limit` 或 `--rumors`。结论与文件同时交付时，使用同一入口的 `complete --artifact-relative ... -- <业务参数>` 完成运行、收据绑定和交付授权。

## 固定流程

1. 刷新全市场公告、担保、质押、诉讼、停复牌、ST、票交所企业披露、欠薪失信、司法失信、投资者问答和跨平台异常。诉讼域使用东方财富官方重大事项公告中的诉讼、仲裁、执行、冻结与查封记录，不再调用已失效的巨潮诉讼接口。
2. 识别债务逾期、冻结、立案、重大诉讼、重整、持续经营异常、财务减值、股权质押、解禁减持和治理变化。
3. 叠加指数跌幅、涨停数量与本地通达信市场状态，形成市场与技术风险等级。
4. 按 [证据与分级规则](references/evidence-rules.md) 去重并分为硬剔除、前置核查、票据历史异常和市场观察。
5. 运行本轮验证器；任何关键来源、证据完整性或市场风险产物未通过时均阻断。
6. 需要海报时运行固定8K浅色模板和海报校验器，生成整图、1920×1080预览、版式元数据及验证结果；通过 `complete --artifact-relative` 绑定本轮产物，并在最终回复前执行 `authorize --receipt` 验证结论和文件。
7. 需要 Word 时使用“精美Word交付”生成原生可编辑文档，并按同一收据授权规则交付。

## 结果硬闸

- 投资者提问、传闻、价格下跌和热度不能单独写成公司事实。
- 同源转载只计一个源头；公司公告、监管文件、法院文书、票交所披露和财报分别计独立证据域。
- 票据记录必须核对上市公司本体或子公司关系；已结清不得写成仍逾期。
- 没有实际返回行的数据源不得进入分数、名单或正文。
- 诉讼、质押和逐股新闻深挖是独立关键来源域，任一域失败必须阻断；互动易合法空结果保留为空表，不冒充接口失败。
- 非交易日质押日期先回退到最近工作日，质押明细慢源最多占用 12 秒；超时必须写入 `source_health.csv`，不得静默吞掉。
- 解禁减持、解除质押等资本事项默认进入核查层，除非有独立证据支持更高风险分级。
- 市场风险等级只描述环境与失效条件，不证明任何个股存在经营或财务问题。

## 固定产物

- `run_manifest.json`：本轮日期、候选数、证据数和数据源状态。
- `risk_candidates.csv`：全部候选工作队列。
- `front_candidates.csv`：前置核查名单。
- `confirmed_risk_candidates.csv`：已经公开的风险事项。
- `evidence.jsonl`：逐条独立证据及原文链接。
- `market_risk_warning.json`：市场与技术风险叠加结果。
- `integrated_risk_summary.json`：个股排雷与市场预警的合并验收摘要。
- `skill_validation.json`：本轮结果硬闸读回。
- `risk-mine-clearance-8k.png`：7680×4320浅色标准海报。
- `risk-mine-clearance-preview-1920x1080.png`：整图可读性验收预览。
- `poster_metadata.json`：文字字号、位置、分区和预览缩放记录。
- `poster_validation.json`：尺寸、浅色背景、字号和缺字硬闸结果。

最终答复只给核心结论、证据状态和已经授权的可点击产物。
