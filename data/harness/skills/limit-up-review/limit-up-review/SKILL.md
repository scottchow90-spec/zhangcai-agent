# 涨停板深度复盘

## 调用边界

- 仅在用户显式调用 `$limit-up-review` 或逐字点名“涨停板深度复盘”时使用。
- 目标系统是本机 Codex；不得改用其他股票技能、替代入口或临场脚本。
- 当日官方涨停池是唯一原始候选宇宙；必须保留原始集合、哈希和退市硬剔除记录。名称带退市标识的股票不得进入可交付候选、统计、观察池、公式样本、表格或 Word。全市场、指数、行业、概念、炸板、跌停和历史数据只可用于分析对照，不能新增候选。
- 市场事实、行情、公告、新闻、政策和监管信息必须使用本轮新鲜证据，并标注数据时间与来源。
- 输出是有证据边界的研究支持，不承诺收益，不构成确定性投资建议。
- 需要网页交互时只使用用户的 Google Chrome，不得切换浏览器表面。

## 唯一入口

- 正式执行：`python D:\C盘转移\日志\codex\skills\limit-up-review\scripts\codex_entry.py run`
- 用户参数：只能跟在 `run --` 后显式传入。
- 静态检查：`codex_entry.py info` / `codex_entry.py selftest`；检查命令不能代替正式执行。
- 其余脚本只是唯一入口锁定的内部实现，不得由模型直接选择或替换。
- 正式业务历史只能写入 `$CODEX_HOME/business_data/limit-up-review`；隔离测试只能写入本轮 `out_dir`。禁止把复盘 Markdown、CSV、观察池或历史材料写入 `$CODEX_HOME/memory`、`$CODEX_HOME/memories`。

## 强制分析链

严格执行：

`运行契约 → 证据采集 → 质量与缺失 → 20/60 日基线 → 市场结构 → 方向论证 → 个股角色 → Claim Graph → 四分支情景树 → 冻结预测账本 → 业务语义硬闸 → 最后渲染 → T+1/T+N 校准`

关键约束：

- 事实、推断和假设分层；每个关键判断都要有证据、最强反证、置信度依据和失效条件。
- 缺失写 `UNAVAILABLE`，不得填成 `0`；缺失必须降低置信度或使相应结论变为 `INSUFFICIENT`。
- 未经历史校准的评分只能内部排序，不能单独形成可见结论。
- 次日计划必须是加强、轮动、失败、外生冲击四分支情景树，不能是固定观察清单。
- `business_result.json` 是渲染前的唯一分析真相源；模板只映射已经通过语义硬闸的结果，不得生成新结论或兜底判断。
- 可见 Markdown、CSV、观察池与 Word 必须全中文呈现，拉丁字母命中必须为零；内部机器字段只能通过固定中文映射显示，不得直接写入可见产物。

只有以下各层都通过，才可声称完成：

- 官方候选集合、数据时间、来源和哈希可追溯；

- 可见产物没有模板默认结论、固定措辞、兜底判断或未校准分数结论；
- 原始官方池、退市硬剔除记录与可交付池差集一致；可见产物拉丁字母命中为零、退市代码和名称命中为零；
