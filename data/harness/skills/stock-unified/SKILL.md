# 股票技能统一验收入口

## 职责边界

- 目标系统固定为本机 Codex，禁止调用 OpenClaw 网关、旧股票总执行器或迁移源目录。
- 本技能负责统一官方股票技能目录、根入口合同和自检验收口径。
- 具体选股、个股分析、舆情、风险或交付任务仍由对应业务技能根入口执行；本技能不临场代选业务脚本。
- Routing role: validation-only. Implicit invocation is disabled.

## 唯一入口

`python D:\C盘转移\日志\codex\skills\stock-unified\scripts\codex_entry.py run`

唯一执行链：

`codex_entry.py` → 内部统一验收执行器 → 当前权威目录 → 目录内全部根入口逐项自检 → 当前结果 JSON 落盘与回读。

内部执行器不是第二个公开入口，禁止绕过根入口直接调用。

## 硬闸

- 当前目录必须与唯一权威目录一致，且无重复 ID。
- 目录内所有技能必须全部存在 `scripts/codex_entry.py`。
- 根入口不得处于 `PROCEDURAL` 空执行状态。
- 目录内所有根入口自检必须全部返回零退出码和明确 PASS 语义；统一验收最多使用 8 路有界并发，输出顺序仍严格遵循权威目录。
- 当前结果必须落盘、重新解析，并输出当前大小和 SHA-256。
- 所有统一入口子进程必须加载 TdxW/tdxcef 默认拒绝保护；按进程名或受保护 PID 发起的 taskkill、Stop-Process、`os.kill`、psutil terminate/kill/suspend/send_signal 必须在调用前阻断并留下审计事件。
- 业务运行时只串行化同一工作流；不同工作流使用隔离锁并可并发。单次排队上限不得超过 600 秒。
- 可选补充源默认 8 秒超时，并按交易日期复用内容寻址缓存；必需补充源保留 45 秒上限且失败时必须阻断业务。
- 每张业务回执必须记录请求校验、合同预检、排队、绑定校验、证据、补充源、业务子进程和结果验收的分阶段耗时。

## 生产级共同合同

- 53 个权威技能必须逐项绑定同一 `STOCK_PRODUCTION_POLICY_V1`，并通过 19 项生产控制矩阵；技能、合同和矩阵顺序必须与权威目录完全一致。
- “完全无漂移”表示本轮目录、合同、入口、执行器、共享运行时和业务绑定 SHA-256 全部一致，且运行前、运行后和交付授权时再次校验；未来发生任何变更时必须自动阻断，禁止把一次快照解释为永久不变。
- 请求必须严格校验动作、参数类型、控制字符、数量和字节上限；账户、凭据、经纪商、下单、撤单、自动交易等参数或结构化字段一律在业务启动前阻断。
- 业务输出必须是唯一 JSON 对象并包含真实业务进程状态、业务绑定、工件映射和空错误集；输出流合计超过 16 MiB 时必须立即终止本轮业务子进程并归类为 `RESOURCE_LIMIT`。
- 股票结论只有在身份、最新有效交易日、行情/K 线、基本面、新闻公告、板块题材和来源新鲜度七维数据闸门全部有证据且为 `CLEAN_PASS` 时才可授权；纯自检回执永远不得授权为股票结论。
- 回执版本固定为 v4，必须包含合同绑定请求指纹、失败分类、14 阶段遥测、当前生产表面签名和生产就绪对象；53 个适配器的日志/结果、回执、授权和当前验收结果全部使用原子替换并回读哈希。
- 本标准仅覆盖离线研究、分析、信号、模拟和交付可靠性；禁止连接券商账户、交易终端、委托或任何实盘自动交易。

任何一项失败，状态必须为 `BLOCKED`，不得用模板、工作流文字、旧回执或人工说明代替执行。

## 内部维护（不构成业务入口）

- 合并技能组件在经过授权恢复或整改后，使用
  `python scripts/sync_merged_source_manifests.py --check` 检查来源清单；只有精确备份后才可使用 `--write` 更新既有文件的 SHA-256。
- 维护器必须要求组件实际文件集与清单文件集完全一致；不得自动添加、删除或忽略组件文件。
- 该维护器不执行股票业务，也不得替代唯一公开入口 `scripts/codex_entry.py run`。
